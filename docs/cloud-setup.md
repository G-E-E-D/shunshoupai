# 旧版云端资料与迁移边界

本文是 **v1.x Supabase 模式的归档说明**，不是 v2.0.0 的部署教程。v2 使用本机 SQLite 和局域网设备配对；设置 `APP_STORAGE=supabase` 会被拒绝，邮箱注册、密码登录和旧扫码会话不再用于当前运行流程。

## 已有云端资料

升级不会主动删除 Supabase 中的日程或模型配置。请先使用原有部署及数据库管理工具备份或导出旧资料，再规划转入本机。**v2 当前没有 Supabase 自动导入工具、导入向导或导入界面**；不能通过修改环境变量把云端资料直接切换成本机数据，也不能把 PostgreSQL 导出文件直接作为 SQLite 数据库打开。

在完成并验证迁移前，应保留原云端数据库、必要的部署配置与模型加密主密钥。模型密文依赖原空间归属及原主密钥；不要假定只复制记录就能解密。不要在已有云端项目执行测试库的 `bootstrap.sql` 或重跑初始化脚本。

## 已有本机资料

旧本机 SQLite 的升级由应用处理：唯一旧资料自动沿用，多份旧资料仅首次在电脑选择一份，其余仍保留。候选包含仅拥有客户端草稿的旧资料，事件 ID、版本号、草稿键和未确认操作编号不重建。完整规则见[设备配对与升级](device-sync.md)。这套本机升级规则不等同于云端导入能力。

## 归档内容

仓库保留 `supabase/migrations/`、`supabase/tests/` 及部分旧存储代码，用于历史资料参考与回归验证。相关测试通过只说明旧数据库约束仍被检查，不表示 v2 支持托管 Supabase 运行。

当前安装和开发请使用[桌面说明](desktop.md)与[安卓说明](android.md)。安装版会自动准备本机授权；源码开发需将同一份至少 32 字符的随机 `APP_DEVICE_BOOTSTRAP_KEY` 传给本机 Node 和 IP 字面量环回地址上的 Qt `--backend` 进程。

v2 支持电脑和安卓任意两两配对，手机接收同步需保持前台；未提供公网托管或端到端加密同步。设备身份签名不替代 TLS；日常同步以可信局域网为边界。
