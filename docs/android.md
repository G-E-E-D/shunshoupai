# Android 客户端（v2.1.0）

手机打开即进入原生日程，无需账号或电脑连接。手动安排、一句话整理、批量草稿、模型设置、月历和前台提醒均可在手机完成；需要合并另一台手机或电脑的日程时再扫码配对。**配对仅用于同步日程**，不借用对方模型，不开放对方模型设置或其他管理权限。

当前源码为 `versionName=2.1.0`、`versionCode=9`，应用 ID 为 `com.shunshoupai.app`，最低 Android 8.0 / API 26，目标 API 36。已发布安装包见[发布列表](https://github.com/G-E-E-D/shunshoupai/releases)。正式覆盖升级必须使用同一正式签名；不要用卸载代替升级，否则会删除手机本机数据。

应用和本轮新增的屏幕捕获流程使用 Java。中文 OCR 模型随 APK 提供，SDK 内含预编译本机库，构建者不需要另行编译 NDK/CMake 工程。当前 `main` 的电脑日程服务仍为 Next.js/Node；Windows 保留原有主体，新增截图功能使用 Java/Tess4J。Android 不需要运行或连接电脑端服务才能安排日程。

## 手机独立使用

1. **手动安排**：点击“新日程”，填写标题，用原生日期和时间选择器安排起止时间；编辑、完成、恢复和删除都先保存到本机。
2. **智能整理**：描述安排后生成可编辑草稿。核对标题、日期、时间和提示，可修改、移除或取消勾选条目，再点击底部始终可见的“保存已选”。整理不会自动写入正式日程。
3. **草稿恢复**：原文、批量条目和手动编辑分别保留。点击“稍后继续”、旋转或重开应用后可以恢复；恢复不会自动提交。批量保存最多 20 项，整批校验和写入，遇到时间冲突或无效条目会保留草稿供修改。
4. **查看安排**：“日程”查看选中日期，“七天”从选中日期起查看连续七天；点击日期打开月历，也可用左右按钮或“今天”快速跳转。“已完成”查看本机全部已完成项目，可恢复为未完成。

搜索不局限于正在浏览的日期：“日程”和“七天”页搜索全部未完成日程，“已完成”页搜索全部已完成日程。“今天”“明天”等自然语言以实际上海日期为参考，不会因日历翻到其他年份而改变。

## 本机规则与模型设置

未配置模型时，手机使用本地有限规则整理；含糊时间会追问，默认假设会提示。手机完全断网时仍可手动安排、使用规则、恢复草稿和查看日程，本地规则不是离线大模型。

点击“模型”可配置自己信任的兼容接口、模型名称和 API Key。手机直接请求该服务，电脑不参与转发；电脑关闭但手机能连接模型服务时，模型仍可使用。测试连接不会自动保存配置，失败不会清空原文或未提交草稿，也可明确选择“仅用离线规则”。

模型 Key 使用 Android Keystore 加密保存，不随配对和日程同步传播。修改配置时，同一来源可留空保留原 Key；换来源需要重新填写，不能把旧 Key 带给新地址。默认使用公网 HTTPS；使用可信局域网模型地址需要在手机明确启用相应选项。详见[模型设置](model-settings.md)。

## 悬浮屏幕取字

此功能默认关闭，首次打开应用不会强制请求悬浮或截屏权限。

1. 点击首页“取字”，阅读说明并主动开启。按系统界面允许悬浮显示，再选择分享单个应用或整个屏幕。通知权限可选；拒绝后不会每次使用都重复询问。
2. 切到需要取字的页面，点击可拖动的悬浮按钮。在已捕获画面的本机预览中拖出选区，再点击“识别选区”。受保护画面不能绕过系统限制，可能显示黑屏或无法识别。
3. 在“识别文字”页核对、编辑原文，点击“整理成草稿”。空白工作稿会直接开始整理；若已有原文或未确认草稿，则先选择追加或稍后处理，不静默覆盖，也不自动重排旧稿。
4. 草稿生成后仍须检查并点击“保存已选”，才会成为正式日程。待处理文字也可稍后从智能整理中取回；普通查看不会自动调用模型。

同一次用户开启的授权会话可连续框选，不必每次截图都重新授权。前台通知清楚标识捕获状态并提供停止操作；也可长按悬浮按钮停止，或回到首页“取字中”停止。在本应用前台时暂时隐藏悬浮按钮，避免遮挡编辑。停止、锁屏或系统撤销捕获后，下次开启必须重新取得系统授权，不保存可重复使用的截屏授权。

图片只短期保存在本机内存，用于裁切和 OCR，不写入相册、不通过配对传播，也不发送给日程模型；无需媒体读取权限。识别文字超过 2000 字时需自行删减，不会自动截断。**点击“整理成草稿”后，如果手机配置了模型，确认后的文字会按当前设置发送给该模型服务**；图片始终不发送。

中文 OCR 模型随包可离线首用。识别组件可能发送性能和使用统计，不能把“图片在本机处理”理解为组件完全不联网。参见 [ML Kit 条款](https://developers.google.com/ml-kit/terms)和[第三方说明](../android/THIRD_PARTY_NOTICES.md)。

## 配对、同步与本机数据

需要同步时，任一手机或电脑在设备连接入口展示一次性二维码；两端连接同一可信局域网，另一端扫码或粘贴链接，并确认共享范围。支持安卓↔安卓、安卓↔电脑和多设备连接，无需固定中心电脑。Windows 安装版通常监听 **43127**，手机地址和端口以配对页面为准；手机的 `localhost` 指手机自己。

二维码 90 秒有效，只能兑换一次；重新生成会作废该入口的旧码。原生配对不加载对方网页，长期凭据使用 Android Keystore 加密保存。普通地址不是授权凭据，未配对设备不能借此读取日程。

每台手机有一份本机主日程。配对会合并双方全部正式日程和未来修改，也可能经对方继续传播至其他已配设备；未确认草稿和模型密钥不随日程同步。取消配对停止后续授权，保留各设备已有副本，不能撤回已经传播的数据。离线解除时，也应在另一端设备列表中撤销授权。

不同日程重叠时保留双方并提示；同一日程发生并发修改或删除冲突时保留不同版本，显示标题、时间、状态和来源，由用户明确选择。同步使用不可变修订和完整祖先关系，重试及环路传播不会重复创建或复活旧删除；编辑仍基于打开时实际看到的版本。

地址变化后，必须在原设备生成新二维码并重新扫描。手机核对稳定身份和已记录公钥后继续同步，新地址不会收到旧长期凭据。身份签名不提供 HTTP 通道加密，不能替代 TLS；只应在可信局域网配对。

升级保留旧日程、版本、待确认操作编号及仅有表单草稿的旧空间。历史资料继续独立保留，明确导入后才合入主日程，其他来源不会因为空间 ID 相同或新配对就自动混入。v2.0.0 的“电脑工具”网页入口属于旧流程，当前版本已移除。

## 前台与后台边界

- 日程修改先保存在本机，断线不清空内容；手机在前台及回到应用时静默尝试同步。
- 手机只在前台开放接收服务。退到后台、锁屏或关闭应用后不保证同步；两端保持打开且网络互通时再合并。
- 本机提醒默认关闭。启用后在日程开始前五分钟提示；已完成、已删除及待处理冲突不会提醒。提醒只在应用前台运行，不是系统闹钟或可靠的后台通知承诺。
- 屏幕捕获服务只处理用户开启的取字会话，不启动后台日程同步、提醒或模型请求。它的前台通知不改变上述边界。

## 从源码构建与验收

需要 JDK 17 或兼容版本、Android SDK Platform 36、Build Tools 35.0.0，以及仓库内 Gradle Wrapper。

```sh
cd android
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

Windows 使用 `gradlew.bat`。正式签名通过 `ANDROID_KEYSTORE_PATH`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` 环境变量提供，再运行 `./gradlew :app:assembleRelease :app:lintRelease`。调试签名不能覆盖正式包；密钥、APK、数据库和构建缓存不提交 Git。

2026-10-28，当前 `main` 2.1.0/code9 在 API 36 模拟器完整 instrumentation **110/110** 通过，在 API 35 模拟器捕获流程与裁切测试 **12/12** 通过，均未发现应用崩溃或 ANR。另有本轮 OCR 模块首次安装、关闭 Wi-Fi 和移动数据后的 **5/5** 离线识别验证。构建、Lint、64 位 OCR 库与 APK 的 16 KB 对齐检查通过。

这些结果不等同于正式签名安装器已经发布，也不代表全部厂商真机、相机或第三方模型服务均已验证。测试版本、截图和能力边界见[手机独立体验矩阵](mobile-parity.md)，整体发布验收见[验收记录](acceptance.md)，同步协议见[设备配对](device-sync.md)。
