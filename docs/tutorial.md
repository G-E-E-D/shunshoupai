# 不想一条条填日历，我做了个能整理日程的小工具

准备面试时，安排很容易写成一长串：“今天改简历，明天下午面试，晚上再准备一下。”真正打开日历，却还要反复点日期、填标题、选起止时间。顺手排把重复工作缩短成三个动作：写下来、看一眼、确认保存。

## 电脑先装，手机接着用

从 GitHub Releases 下载 Windows 安装 EXE，双击后即可打开原生 Qt 桌面窗口，不需要浏览器，也不用另外安装 Node。安装包带有本地服务，打开应用时自动运行，关闭应用时结束。仓库只保留源码、构建脚本和文档，安装包在发布页下载。

第一次点击“登录 / 注册”，选择注册，填写自己的邮箱和至少八位密码。本地模式的邮箱是账号标识，不发送验证邮件，没有预设的共享账号。账号和日程保存在用户目录的 SQLite 数据库中，重启应用后仍然存在；登录状态只在桌面进程中保留，重开应用需要登录。

左侧写下安排，右侧查看正式日程。没有模型配置时，窗口会明确显示“规则体验”，使用有限的中文时间规则。这能先验证保存和同步流程，不能当作真实模型演示。前台提醒可开启，但应用退出或锁屏后不保证提醒，不把站内提示包装成系统闹钟。

## 从一句话到三项草稿

可以点击“试试示例”，或手动输入：

> 明天下午三点到四点面试，今天晚上七点到八点改简历，八点到九点准备面试。

点击“帮我整理一下”后，先检查弹出的草稿表格。它会显示具体年月日、标题、开始与结束时间。明天的面试和今天晚上的两项准备，应该分到不同日期；不要只看“明天”两个字。你可以修改标题和时间，移除其中一项，或暂不保存。

确认后，记录才进入右侧日程。这里可以切换当天与七天，搜索已加载的安排，修改、完成、恢复或删除。时间统一使用上海时区。新建单项日程也可以手工填写，不必把每件事都交给模型。

如果只写“明天晚上七点跑步”，程序会显示缺少结束时间所采用的默认时长，仍由你决定是否保存。写“周五三点面试”，它会追问上午还是下午；写“每周一”或“全天”，会说明当前限制，不会悄悄删掉这些词再生成单次安排。

## 换成自己的模型

桌面点击“模型设置”，填写服务商的 Base URL、真实可用的模型名称和自己的 API Key。接口需要兼容 Chat Completions，并支持 JSON 输出。先点“测试连接”，成功后再点保存；测试会发起一次小请求，可能消耗服务商额度，不会自动保存。

日程提示词固定在服务端代码中，用户无需填写。同一账号在安卓端也使用相同配置。Key 加密存储在所连接的服务端，界面只显示掩码，不会读回原文。已有密钥时留空可保留；更换接口来源后需要重新填写，避免误把旧 Key 发给另一个服务。

这仍要求信任所连接的顺手排服务：服务运行时需要解密 Key 才能调用模型。公网使用 HTTPS，不把密钥提交到 GitHub、放进截图或转发聊天。没有真实模型账号时，继续使用明确标记的规则模式即可。

## 扫一下，手机直接登录

手机安装新版安卓 APK，和电脑连接同一个可信 Wi-Fi。电脑登录后点击“手机扫码登录”，选择手机可访问的局域网地址，生成登录码。安装版默认端口为 43127，电脑应保持应用运行，并允许可信局域网访问这个端口。

安卓首页点击“扫码连接”，授权相机后扫描。应用会连接同一服务，并自动登录电脑上的账号，不必再次输入密码。码只有九十秒有效，而且只能使用一次；它是临时登录凭据，不要截图转发。没有相机或拒绝权限时，也可手工填写服务地址，再正常登录。

手机保存后，电脑前台约八秒补拉，也可手动刷新。数据来自同一个服务端数据库，两台设备各跑一份独立服务不会自动同步。需要公网或多个服务实例时，再按文档使用 Supabase；云端扫码授权有明确到期时间，到期后重新扫码或密码登录，不复制长期刷新凭据。

## 真正需要反复检查的部分

我用 Codex 辅助实现与测试，桌面采用 C++ / Qt，安卓在原 Java 工程中加入 NDK / JNI，共用地址与扫码协议核心。最耗时间的并非输入框，而是上海午夜之后“明天”究竟是哪天，以及保存请求断线后会不会多出一份安排。

解析使用服务端参考时间，保存使用固定编号。同一请求重试返回原结果；结果未知时保留编号继续核实。两端同时修改同一项，较旧版本会被拒绝。批量保存还会在事务内检查时间冲突，有一项冲突就不会悄悄保存一半。

现阶段适合个人的单次学习、求职和生活安排。源码、Windows 安装器、安卓 APK 和运行文档已经作为交付目标；实际自动化结果以验收记录为准。真实模型、托管云端、相机与手机网络需要各自的外部环境验证，演示视频尚未发布。
