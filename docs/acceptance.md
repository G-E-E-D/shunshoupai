# 实现与验收记录

本记录区分源码实现、本地已执行验证、整包流水线结果和仍需外部环境的验证。当前版本 v1.2.0，日期 2026-10-27（上海时区）。

## 实现

| 部分 | 行为 |
| --- | --- |
| 桌面 | C++17 / Qt Widgets 原生前端，Qt Network 调用共用 API；没有浏览器壳 |
| 安卓 | 保留 Java 工程、相机、WebView，NDK / JNI 调用共用 C++ 连接核心 |
| 日程 | 文本整理、可编辑草稿确认、增删改、完成/恢复、当天/七天、搜索、上海时区 |
| 账号与同步 | SQLite 或可选 Supabase；同服务同账号，前台约八秒补拉 |
| 个人模型 | 按账号加密保存接口、模型名和 Key，测试连接、掩码元数据，固定服务端提示词 |
| 扫码登录 | 90 秒一次性高熵码，fragment 传递、原子兑换、清除 fragment；本地独立会话，云端明确授权期限 |
| 保存保护 | 事务内时间冲突、批量回滚、原请求防重、版本冲突、结果不明保留编号核实 |
| 分发 | Windows 当前用户安装器，包含 Qt / Node / 后端；Android 正式签名 APK；二进制不提交源码仓库 |

## 整包 CI

Windows 安装器和 Android / NDK 整包将由当前源码流水线重新构建验证；完成后的具体运行链接、安装器校验和设备测试统计会在发布前补入本节。未通过的流水线不会记为通过。

Windows 验收脚本验证静默安装、分发内的 Qt / Node、原生 API / 控件、默认启动与停止内置服务，以及重装/卸载保留隔离用户数据库。Android 验收脚本安装正式签名 APK，再运行调试测试包的 7 项设备测试，验证 JNI 协议、真实 WebView / API 与扫码同账号登录。

历史 v1.1.0 的 [Android CI 40493822690](https://github.com/G-E-E-D/shunshoupai/actions/runs/40493822690)包含 5 项设备测试通过，只对应旧版本。正式安卓签名证书 SHA-256 为 `f1dd120e4936926c29308e21262013737b3a2747043a638dfb31a9a811afc87b`，新 APK 应沿用该证书。

## 外部环境边界

- 实体手机相机的拍摄、对焦和二维码识别，实体手机/蜂窝网络与公网 HTTPS 访问。
- 真实模型账号的型号、额度、耗时和输出效果。
- 托管 Supabase 的邮件、认证、Cookie、PostgREST 和两账号完整联调。
- Windows 安装器没有商业代码签名证书。
- 可靠后台/锁屏提醒、离线合并、iOS、循环日程、自动空档排期和外部日历同步尚未实现。
- 没有已托管公网 Demo、已发布视频或第三方用户验收结论。

源码仓库保留代码、构建配置、文档和必要 Wrapper；截图、EXE、APK、数据库和本地密钥在忽略目录、CI 附件或 Releases。升级和卸载不删除用户数据。Supabase 已有部署须追加个人模型和扫码配对迁移，并保持加密主密钥稳定。

## 人工复现

1. 安装并打开 Qt 桌面，注册自己的虚构账号，输入 README 示例句；取消草稿不应产生正式日程。
2. 再次整理并确认，重启应用、重新登录后应仍能查询；修改、完成/恢复、删除行为正常。
3. 保存个人模型配置，在安卓同服务同账号查看；Key 只显示掩码。
4. 电脑生成登录码，安卓扫码后应自动登录同账号；已用或过期码应要求重新生成。
5. 两端同时编辑同一版本，旧版本应被拒绝。断网或丢响应时使用原保存编号核实，不重复创建。
6. 注册第二账号，不应查看或修改第一账号的事件与模型配置。
7. 重装、卸载后确认用户数据目录保留；按需要备份数据库与同目录加密主密钥。
