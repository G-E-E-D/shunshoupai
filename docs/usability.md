# 易用性改进与使用边界（v2.1.0-beta.2）

日期：2026-10-28。电脑与手机需一起升级到 v2.1.0-beta.2。本版原则是打开即可使用，只有建立设备共享关系或处理真正的冲突时才要求用户操作。

## 日常使用

- 电脑安装版自动启动本机服务和授权，不需要注册、登录或维护账号会话；手机无需配对也能新增、编辑、完成、删除和搜索日程。
- 同步时在可信局域网扫描一次性配对码或粘贴配对链接。支持电脑↔电脑、电脑↔安卓、安卓↔安卓及多设备连接，手机前台及回到应用时自动尝试合并。
- 断线期间继续本机保存。每台设备维护自己的主日程；取消配对不会删除已保存或已传播的数据。
- 手机现在拥有完整原生工作台：本机一句话规则整理、手机直连模型、可编辑批量草稿、月历/七天/已完成和前台提醒。配对只同步日程，无法调用对端 AI 或模型设置。

## 保存与合并

本机持久保存不可变修订及完整祖先关系。丢响应、重启、重试和多设备环路传播会合并相同修订，不重复创建；请求期间继续编辑产生新修订。删除也是保留因果历史的修订，某一分页没有出现记录不代表它已删除。

不同日程时间重叠时都保留并提示。同一日程两端都修改、或删除与编辑冲突时，保留全部不同内容并展示版本选择，不按时间或设备 ID 自动选胜者。相同内容的多个修订合并展示，但保留因果信息。编辑草稿保留用户实际编辑时的原版本；解决冲突期间若又收到修改，必须重新核对选择。

`POST /api/replica/exchange` 在已配对设备间分页交换日程及修订，不依赖共同账号或空间。每项最多 32 个并发修订、每修订最多 2048 个祖先，超限明确拒绝，不截断历史。旧同步接口仅兼容历史请求；未经配对的局域网请求不能访问日程。

## 减少的重复操作

| 使用中的打断 | v2.1.0-beta.2 行为 |
| --- | --- |
| 开始使用前填写身份信息 | 取消账号流程，安装版直接准备本机日程 |
| 手机必须等电脑在线 | 全部日程操作与整理流程在手机完成，模型也由手机直连自己的服务 |
| 网络失败后反复手动恢复 | 保留数据与配对关系，前台自动重试 |
| 慢请求被轮询反复作废 | 等待当前请求完成 |
| 无变化刷新移动焦点和滚动位置 | 无变化时保留现有控件 |
| 关闭或刷新丢失草稿 | 保留整理草稿及手动编辑，确认后才保存正式日程 |
| 恢复旧稿意外覆盖另一端 | 保留原版本，冲突时明确选择 |
| 手机修改开始时间还要重算结束 | 保持原时长，支持跨天 |
| 手机网页先滚过输入区才能看安排 | 完整原生工作台，一句话安排直达本机草稿；批量保存按钮固定在底部 |
| 操作控件过小或被系统手势遮挡 | 增大常用触摸区，适配底部安全区 |
| 升级后旧草稿失去归属 | 沿用被选择的旧空间 ID，保留版本与操作编号 |

## 地址与旧资料

配对前明确告知：本机全部日程及未来修改可能经对方继续传播到其他已配设备，解除配对无法撤回历史副本，模型密钥不传播。

IP 地址变化后必须在原设备生成新二维码并重新扫描。核对稳定身份后继续同步，不向新地址发送旧凭据。签名用于识别设备，不提供 HTTP 加密；可信局域网仍是使用边界。

旧本机资料只有一份时沿用，多份时首次由本机用户选择。历史分区及表单草稿保留，明确导入后才合入主日程；同 ID、不同来源的资料不会自动混合。旧 Supabase 资料不被删除，但当前没有运行模式或自动导入界面。

## 尚未提供

可靠后台/锁屏提醒、安卓后台同步、内置离线大模型、电脑后台驻留和公网托管尚未实现。有限规则整理在手机断网时可用，不能把它当作离线大模型。安卓接收服务仅在应用前台运行；关闭或进入后台后不承诺准点提醒或持续同步。

Web 远端日程被删除或移出当前加载范围时，本机编辑稿仍保留，但原列表没有直接重新打开该稿的入口。少见的“编辑器仍开着时，自己的旧上传刚好确认”可能触发保守的版本核对；内容仍保留。
