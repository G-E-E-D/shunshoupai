# 易用性改进与使用边界（v2.2.0）

当前使用原则是打开即可安排，断线继续保存，重复操作尽量由程序完成；共享日程、发送确认文字或解决真实冲突时，由用户明确选择。电脑和手机都可独立使用，配对仅负责日程同步。

## 每次使用尽量少打断

| 过去容易产生的重复操作 | 当前行为 |
| --- | --- |
| 开始前注册、登录或维护会话 | 取消账号流程，安装版直接准备本机身份与日程 |
| 手机等待电脑在线才能整理 | 手机有本机规则、模型设置、批量草稿和日历视图 |
| 网络失败后重新输入 | 保留本机内容和配对关系，后台及网络恢复时自动重试 |
| 没有变化也重建列表 | 内容未变时尽量保留控件、滚动位置和编辑焦点 |
| 退出、旋转后重写草稿 | 原文、批量草稿和手动编辑分别保留，恢复不自动提交 |
| 保存按钮随长草稿滚出屏幕 | 手机“保存已选”固定在草稿页底部 |
| 手工输入日期格式 | 原生日期/时间选择器、月历、前后翻页和“今天”入口 |
| 浏览别的日期后“明天”解释错位 | 自然语言固定以实际上海日期为参考 |
| 从其他页面抄录日程 | 电脑 Ctrl+Alt+S 或截图按钮；手机主动开启悬浮框选，OCR 后核对文字 |
| 连续取字反复走入口 | 电脑可选浮窗；手机同一授权会话可连续框选 |
| 取字浮窗挡住自己的草稿 | 手机回到工作台时隐藏悬浮按钮，首页保留停止入口 |
| 恢复旧编辑覆盖另一端修改 | 保留编辑开始时版本，发现并发内容后明确处理 |
| 升级丢失旧草稿归属 | 保留被选择资料的 ID、版本、草稿和原操作编号 |

Windows 主体继续使用 Qt，新增截图、快捷键、浮窗和文字确认使用 Java，OCR 使用 Tess4J/Tesseract。Android 使用 Java 原生工作台和捕获流程，OCR 模型随 APK 提供。当前电脑日程服务仍是 `main` 的 Next.js/Node。

## 日程、草稿和模型

手机手动操作和批量整理都在本机完成。有限规则可以断网运行；用户配置模型后，手机直接请求该服务，电脑关闭不会强制阻塞。模型网络失败或响应无效时保留输入，可明确改用规则。

整理只生成草稿，用户可修改、移除或取消勾选后再保存；批量保存按一个整体校验并写入，失败不部分落库。退出草稿页不是提交，恢复也不会自行保存。模型 Key 各设备独立加密，测试配置不等于保存，配对不能读取或修改对方模型。

手机“日程”看选中日期，“七天”从选中日期起算七天，“已完成”保留全部已完成项目。搜索在未完成或已完成类别内覆盖全部日期，文案明确范围。

## 取字时保留必要确认

Windows 可以点击“截图”或按 Ctrl+Alt+S；浮窗默认关闭，在截图设置中开启。取消框选不会整理或保存。识别后用户核对原文，已有输入默认追加，也可明确选择替换；尚有日程草稿或保存结果待核对时，先处理原工作。暂时关闭的识别文字使用当前 Windows 用户 DPAPI 加密保留，确认交接重试沿用同一编号，避免重复追加。

Android 取字默认关闭，用户主动开启才请求悬浮与系统屏幕捕获授权。一次授权会话可连续截图；停止或系统撤销后，下次必须重新授权。前台通知、悬浮按钮菜单和首页均可停止；通知权限拒绝后不每次重复询问，其他停止入口仍可用。锁屏会结束取字会话。

两端识别后都先展示可编辑文字，超过输入上限时保留原文并要求删减，不自动截断。手机已有输入或草稿时先询问追加或稍后处理；普通查看待处理文字不会自动调用模型。生成草稿后还要确认保存正式日程。

图片只在本机短期处理，不上传模型、不随日程同步。配置模型时，用户确认后的文字可能发往当前设备设置的模型服务，确认页说明这一点。Android ML Kit 可能发送性能和使用统计；“本机 OCR”不等于组件零联网。受保护画面不会绕过系统限制。

## 保存与合并

本机持久保存不可变修订及完整祖先关系。丢响应、重启、重试和多设备环路传播合并相同修订，不重复创建；请求期间继续编辑产生新修订。删除保留因果历史，某一页没有出现记录不代表它被删除。

不同日程重叠时保留并提示。同一日程两端都修改，或删除与编辑冲突时保留不同内容，展示版本选择，不按设备时间自动选胜者。相同内容可合并展示，但保留因果信息。编辑草稿保留用户实际看到的版本；解决冲突期间又收到修改时，需要重新核对。

配对前明确告知共享本机全部正式日程及未来修改，内容也可能经对方传播到其他已配设备。未确认草稿、模型密钥和截图不传播。解除配对停止后续授权，已有副本保留；不能撤回历史传播。

IP 地址变化需在原设备生成新二维码并重新扫描。核对稳定身份后继续同步，不向新地址发送旧凭据；身份签名不提供 HTTP 加密。同步仅面向可信局域网，完整协议见[设备配对](device-sync.md)。

## 前台、后台与验证范围

- 手机数据先本机保存，后台连接与系统任务继续自动合并。首次集中设置通知与锁屏运行，后续不重复弹窗；断线退避重试，重启首次解锁后恢复。
- 日程提醒使用系统闹钟，开始前五分钟通知，后台和锁屏可用。新安装默认启用，旧版显式关闭保持；完成、删除、改期及冲突会重新核对，进程重启不重复提醒。
- 后台同步可从通知暂停，不删除配对和日程；系统强行停止后需重新打开。厂商电池策略、深度休眠和通知权限会影响运行，详见[后台说明](background-operation.md)。取字服务仍只维持独立授权的捕获会话，不调用模型。
- Windows 退出主程序后，随本次启动的本机服务、Java 截图进程、快捷键和浮窗退出，不承诺退出后后台驻留。截图需要可交互桌面，锁屏环境的内存 OCR 测试不能证明物理捕获通过。
- 本机规则和随包 OCR 可离线使用，互联网模型仍需要网络；当前不提供离线大模型或公网托管承诺。

历史资料只在明确选择或导入后进入主日程；不同来源不因同一 ID 自动混合。旧 Supabase 资料保持原样，但没有当前运行模式或自动导入界面。

Android 各版的本地证据、API 35/36 范围与截图见[手机能力矩阵](mobile-parity.md)。Windows 物理截图、正式签名与安装器发布结果以[验收记录](acceptance.md)和对应 Release 为准；不把配置好的 CI 检查写成已经通过。
