# 易用性改进与使用边界

日期：2026-10-27。本文对应 v1.4.0；使用本次功能需将手机与电脑一起升级。

## 日常使用

- 电脑首次登录后，Windows 使用当前系统用户的 DPAPI 加密保存 Cookie。再次启动自动恢复，网络失败自动重试；主动退出即清除本机凭据。按完整服务地址和端口隔离，不存储密码。
- 默认本地模式的会话 30 天有效，活跃使用每日续期；超过有效期未使用或主动退出后需要重新登录。Supabase 密码登录遵循其刷新会话，临时扫码授权仍遵循原 JWT 到期时间。
- 手机启动即进入本机日程，无需注册、扫描或等待电脑在线。日程可新增、编辑、完成、删除和搜索，时间通过原生选择器输入；修改开始时间自动保持时长。
- 第一次关联电脑时，将此前未关联账号的手机日程合并到该账号。之后日程按服务和账号独立存储，切换账号不会自动搬走旧账号的内容。
- 手机在前台及回到应用时自动重连；没有网络时继续本机保存。智能整理、模型设置、Web 工作台仍需要服务在线。

## 合并规则

不同 ID 的日程完整保留，包括两台设备安排在同一时段的情况，手机显示“时间重叠”，不阻止数据合并。同一条日程如果两端都修改，或者一端删除而另一端修改，手机保留修改稿并提供“使用电脑版本”或保留手机内容的处理入口。

本机 SQLite 将待同步操作编号和原始内容持久保存。网络丢响应、进程重启及重复发送不会重复创建日程。已发出的操作保持不变；请求期间继续编辑会生成后续操作。服务端按账号保存幂等回执，旧版本不能覆盖新版本。删除使用 tombstone，不会因为断网重连而复活。分页没出现某条日程不表示它被删除。

API 为 `POST /api/events/sync`：校验 `account_id`，每批最多 20 项不可变 `mutations`，返回逐项结果和每页 200 项含删除标记的记录。每轮从头扫描，使用 `next_cursor` 拉取后续页；客户端按照版本合并。SQLite 自动建表，Supabase 需追加 `20261027030000_offline_sync.sql`。

## 整体审查后落实的改进

| 原有打断 | 当前行为 |
| --- | --- |
| 重启电脑重新输入账号密码 | 加密持久登录，启动自动恢复 |
| 启动时临时离线后一直显示未登录 | 自动重试会话，不因网络失败清除身份 |
| 手机先连接电脑才有界面 | 原生本机日程先打开，后台尝试同步 |
| 慢请求被定时刷新反复作废 | 等当前请求完成，保留可用界面 |
| 桌面无变化刷新也替换控件 | 无变化时保留控件、焦点和滚动位置 |
| Web 刷新丢失编辑过的整理草稿 | 按账号保存草稿，恢复后继续确认 |
| 桌面“暂不保存”丢失改过的表格 | 单独保留未提交表格，恢复编辑不会自动保存到日程 |
| 手动编辑关闭后丢字 | 三端按账号保留编辑内容，提供明确放弃入口；安卓支持旋转后恢复 |
| 编辑期间另一端更新，恢复草稿可能覆盖新版本 | 编辑保留原版本，发现冲突后明确选择再保存 |
| 改开始时间还要重算结束时间 | 保持原时长，支持跨天 |
| 手机上查看日程要先滚过大输入区 | Web 日程优先，“一句话安排”直达输入 |
| 小屏操作难点中、底部遮挡 | 常用触摸区扩大，适配底部安全区 |
| 每次重开重新调整偏好 | 桌面保存视图、提醒开关及按账号隔离的输入文字 |

## 仍需后续实现的体验

可靠的锁屏/后台提醒、安卓后台同步、离线 AI 整理、电脑后台驻留及公网托管尚未实现。应用退出或手机后台被系统限制时，不承诺自动同步或准时提醒；回到手机应用后会继续同步。局域网服务地址变化时仍需重新连接；手机按完整服务地址隔离数据，新地址会建立独立分区，旧地址下尚未同步的修改仍保留在旧分区，需要恢复原地址后同步。跨地址可信设备识别和数据迁移尚未实现。Web 同条目版本冲突提供版本对比与明确选择；远端已经删除或移出当前加载日期范围时，本机编辑草稿仍保留，但不能从原列表直接重新打开。

默认本地模式适合本次“手机独立使用、连接电脑后合并”的流程。若希望远隔两地也持续同步，需要可访问的共同服务；本次未部署外部服务。

为了保护编辑内容，少见的“编辑器还开着时，自己的旧上传刚好确认”也可能触发保守的版本核对。手机稿仍保留，不会自动覆盖或丢弃。
