# 为本机日程配置模型（v2.1.0-beta.2）

电脑和手机各自保存、使用自己的模型配置，手机不需要先连接电脑。配对仅同步日程，不共享模型 Key、配置、AI 调用或设备管理权限。顺手排不需要账号；模型服务商自己的 API Key 和额度仍由用户提供。未配置模型时，界面明确显示有限规则解析。

## 设置步骤

1. 在要使用模型的那台设备上打开“模型设置”。手机未配对时也可以设置。
2. 填写 **Base URL**、**模型名称**和 **API Key**。Base URL 是模型接口根地址，例如 `https://api.example.com/v1`，程序自动追加 `/chat/completions`。
3. 点击“测试连接”，核对实际可用性。测试会发送一次小型模型请求，可能消耗额度，但不会自动保存。
4. 点击“保存配置”。之后这台设备整理日程时使用这份配置；另一台设备需要独立设置。

接口需兼容 Chat Completions 和 JSON 输出，模型名称以服务商实际提供的 ID 为准。已有 Key 时留空可保留同一接口来源的密钥；修改模型名不必重填，更换接口域名或端口则需重新填写 Key。页面只显示掩码，不回显密钥原文。

移除配置需明确确认。手机随后回到规则解析；电脑如设置了进程默认模型则使用该模型，否则也回到规则解析。移除配置不会删除日程或取消配对。配置具有版本号，旧表单不能覆盖已经更新的配置。

## 联网和数据边界

模型请求由当前设备直接发往用户配置的接口，输入文本会发送给该模型服务。电脑关闭不影响手机自配模型；手机需要能连接该模型接口。完全断网时手机仍可手动安排、使用有限规则、恢复草稿和查看日程，不能请求互联网模型。规则不等于离线大模型。

系统提示词由应用固定维护，包含参考日期、上海时区和输出格式。Go 服务实现位于 `backend/internal/app/parser.go`，手机实现位于 `android/app/src/main/java/com/shunshoupai/app/LocalPlanningParser.java`。设置界面不接受提示词覆盖。模型结果必须经过结构和时间校验，再由用户核对草稿并明确保存；解析本身不写入正式日程。

设备配对码和模型 Key 是两种不同凭据。二维码不包含模型 Key；日程可在多设备间继续传播，模型配置和密钥不会通过日程复制协议传播。已配对设备的凭据不能调用对端 AI 或读取、修改对端模型设置。配对码 90 秒有效、仅兑换一次；取消配对撤销后续同步，不能撤回已传播的日程副本。详细连接步骤见[设备配对](device-sync.md)。

## 密钥保存与备份

电脑个人 API Key 使用 AES-256-GCM 加密，认证数据绑定日程空间。手机使用 Android Keystore 的 AES-GCM 密钥加密本机配置；页面只显示已保存状态，不回显原始 Key。调用模型时当前设备需要解密，因此只应向自己信任的设备和模型服务填写 Key。

电脑默认在数据库同目录生成 `model-encryption.key`；安装版通常位于 `%LOCALAPPDATA%/Shunshoupai/data/`。备份需要同时保留 SQLite 数据库和这份密钥。也可用 `MODEL_SETTINGS_ENCRYPTION_KEY` 指定固定的 32 字节随机值的 Base64；已有密文依赖原密钥，不要随意更换。手机 Keystore 密钥不通过配对复制，换手机时需重新填写模型配置。密钥丢失后需恢复原备份或重新填写模型 Key。

设备身份签名不提供 HTTP 加密。当前设备直连以可信局域网为边界，不能把身份验证当作 TLS 或端到端加密。源码本机授权密钥另见[桌面开发说明](desktop.md)，它不应交给浏览器或模型服务。

## 本地模型

默认允许解析为公网地址的 HTTPS 模型接口，拒绝重定向、元数据地址及未授权的私有地址。确需访问自己控制的本地模型，可在电脑 Go 进程中设置：

```dotenv
AI_ALLOWED_PRIVATE_HOSTS=localhost,127.0.0.1
```

重启电脑后端后才可填写相应地址，例如 `http://127.0.0.1:11434/v1`。允许列表只填主机，不含协议或端口。

手机设置中可以明确允许所填模型接口访问私有网络，用于自己控制的局域网或手机本机模型；默认关闭。系统元数据、链路本地及多播地址始终拒绝，重定向也不跟随。`127.0.0.1` 始终指发出请求的设备：在手机填写时指手机自己，在电脑填写时指电脑自己。访问局域网模型不需要日程配对，它是用户单独配置的模型服务。

## 旧版与验证

v1.x 的账号模型配置、Supabase 及扫码临时会话属于历史实现。v2 沿用被选择的旧本机空间及密文归属，不提供 Supabase 运行模式或自动导入界面，见[旧云端资料说明](cloud-setup.md)。

自动化使用受控模型验证配置、脱敏、Key 留空复用、版本冲突和固定提示词，不使用真实个人 Key 或付费模型。真实服务商的网络、额度和效果需自行验证；完成范围见[验收记录](acceptance.md)。
