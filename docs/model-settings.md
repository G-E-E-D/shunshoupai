# 为本机日程配置模型（v2.2.0）

手机和电脑各自保存模型配置、各自连接模型服务。手机未配对也能整理日程，无需电脑在线。**配对只同步日程，不共享模型设置、密钥或模型调用权限。** 顺手排不需要账号；模型服务商自己的 API Key 和额度仍由用户提供。

## 设置步骤

1. 电脑打开“模型设置”；安卓在日程首页点击“模型”，打开“本机模型设置”。
2. 填写 **Base URL**、**模型名称**和 **API Key**。Base URL 是模型接口根地址，例如 `https://api.example.com/v1`，程序自动追加 `/chat/completions`。
3. 点击“测试连接”。测试由当前设备直接发送一次小型模型请求，可能消耗额度，但不会自动保存配置。
4. 电脑点击“保存配置”，手机点击“保存本机设置”。这份设置只影响当前设备；另一台设备需要单独填写，可以选择不同服务或模型。

接口需兼容 Chat Completions 和 JSON 输出，模型名称以服务商实际提供的 ID 为准。已有 Key 时留空可保留同一接口来源的密钥；修改模型名不必重填，更换协议、域名或端口则需重新填写 Key。界面只显示掩码或“已保存在手机”，不回显密钥原文。

清除配置需明确确认，不会删除日程或取消配对。手机清除后回到本地规则；电脑若配置了进程默认模型则使用该默认模型，否则使用规则。配置具有版本号，同一设备上的设置已变化时需重新读取，防止旧窗口覆盖新设置。

## 离线规则与联网模型

有限规则解析在本机执行，不需要配对或联网，也不是离线大模型。手机没有模型配置、没有可用网络，或选择“仅用离线规则”时使用规则；电脑未配置个人模型及进程默认模型时使用规则。规则只处理支持的明确日期和时间，不能确定的内容会要求补充，不擅自创建日程。

调用模型时，手机直接连接手机配置的服务，电脑通过自己的本机 Node 服务连接电脑配置的服务。模型需要当前设备能访问该接口；模型请求失败或结果无效时显示错误、保留原输入和草稿，不自动保存正式日程。手机可继续点击“仅用离线规则”。电脑在已配置模型请求失败时报告错误，不自动切换到规则。

发送给模型的内容包括本次输入、参考时间、上海时区和用于避让冲突的日程起止时间。两端使用固定系统提示词：电脑在 `src/lib/parser.ts`，手机在 `LocalPlanningParser.java`；设置界面不接受提示词覆盖。结果必须经过结构和时间校验，用户检查并确认草稿后才写入正式日程。

配对网页只提供日程访问，智能整理和模型设置入口隐藏；配对 Cookie 或 Bearer 调用这些接口会被拒绝。模型 Key 不在配对二维码或日程复制协议中，取消配对也不会清除任一设备自己的模型配置。连接步骤见[设备配对](device-sync.md)。

## 密钥保存与备份

电脑 API Key 使用 AES-256-GCM 加密保存，认证数据绑定本机日程空间。读取接口仅返回掩码和配置元数据；浏览器不把 Key 写入 localStorage 或 sessionStorage。模型调用会把 Key 发送给所填服务，只应填写自己信任的服务地址。

本机默认在数据库同目录生成 `model-encryption.key`；安装版通常位于 `%LOCALAPPDATA%/Shunshoupai/data/`。备份需要同时保留 SQLite 数据库和这份密钥。也可用 `MODEL_SETTINGS_ENCRYPTION_KEY` 指定固定的 32 字节随机值的 Base64；已有密文依赖原密钥，不要随意更换。密钥丢失后需恢复原备份或重新填写模型 Key。

安卓将模型地址、名称和 API Key 一起用 AES-GCM 加密，密钥由当前应用的 Android Keystore 保存，密文放在应用私有设置中。它们不写入日程数据库或同步副本。复制设置文件不能迁移 Keystore 密钥；卸载、换机或密钥失效后需重新填写。配置无法解密时会提示错误，仍可使用本地规则，也可明确清除后重填；没有明文存储回退。

设备身份签名不提供 HTTP 加密。当前设备直连以可信局域网为边界，不能把身份验证当作 TLS 或端到端加密。源码本机授权密钥另见[桌面开发说明](desktop.md)，它不应交给浏览器或模型服务。

## 自建模型的网络范围

两端默认只连接公网 HTTPS 模型接口，拒绝重定向、元数据地址及未授权的私有地址。安卓可在本机模型设置中勾选“允许我指定的自建 HTTP / 局域网模型地址”；此选项仅放行受支持的私有或环回地址，系统与元数据地址仍被拒绝，公网 HTTP 不放行。

电脑访问自己控制的本地模型时，可在本机 Node 进程中设置主机允许列表：

```dotenv
AI_ALLOWED_PRIVATE_HOSTS=localhost,127.0.0.1
```

重启后端后才可填写相应地址，例如 `http://127.0.0.1:11434/v1`。允许列表只填主机，不含协议或端口。

环回地址总是指发起请求的当前设备。手机访问电脑上的自建模型时，需要自行填写该模型的可达局域网地址并明确允许私有网络；这是直接访问用户配置的模型服务，不会借用顺手排配对授权或电脑保存的 Key。HTTP 不提供传输加密，只应在信任的网络和服务上使用。

## 旧版与验证

v1.x 的账号模型配置、Supabase 及扫码临时会话属于历史实现。v2.0 的手机 Web 模型代理也已停止作为当前使用流程。v2.1 保留电脑被选择的旧本机空间及密文归属，但不把旧电脑配置导入手机；不提供 Supabase 运行模式或自动导入界面，见[旧云端资料说明](cloud-setup.md)。

自动化使用受控模型验证设备隔离、脱敏、Key 留空复用、版本冲突、固定提示词和手机直连，不使用真实个人 Key 或付费模型。真实服务商的网络、额度和效果需自行验证；完成范围见[验收记录](acceptance.md)。
