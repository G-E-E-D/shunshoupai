# 为本机日程配置模型（v2.0.0）

模型配置保存在当前电脑的本机日程空间，已配对手机可以使用。顺手排不需要账号；模型服务商自己的 API Key 和额度仍由用户提供。未配置模型时，界面明确显示有限规则解析。

## 设置步骤

1. 电脑直接打开“模型设置”。手机需先配对并连接电脑，再打开“电脑工具 → 设备与同步 → 模型设置”。
2. 填写 **Base URL**、**模型名称**和 **API Key**。Base URL 是模型接口根地址，例如 `https://api.example.com/v1`，程序自动追加 `/chat/completions`。
3. 点击“测试连接”，核对实际可用性。测试会发送一次小型模型请求，可能消耗额度，但不会自动保存。
4. 点击“保存配置”。之后整理优先使用这份配置；配对设备连接同一电脑时使用相同设置。

接口需兼容 Chat Completions 和 JSON 输出，模型名称以服务商实际提供的 ID 为准。已有 Key 时留空可保留同一接口来源的密钥；修改模型名不必重填，更换接口域名或端口则需重新填写 Key。页面只显示掩码，不回显密钥原文。

移除配置需明确确认，随后使用电脑进程配置的默认模型；没有默认模型则回到规则解析。移除模型配置不会删除日程或取消配对。配置具有版本号，另一端修改后需核对新版本，避免互相覆盖。

## 联网和数据边界

手机的 Web 智能整理及模型设置需要配对电脑在线。模型请求由电脑发出，输入文本会发送给用户配置的模型服务。手机原生日程的手动记录、编辑和搜索仍能离线使用；离线 AI 尚未实现。

系统提示词固定在 `src/lib/parser.ts`，包含参考日期、上海时区和输出格式。设置界面不接受提示词覆盖。模型结果必须经过结构和时间校验，并由用户确认后才写入正式日程；不会绕过设备授权、版本检查或保存防重。

设备配对码和模型 Key 是两种不同凭据。二维码不包含模型 Key；日程可在多设备间继续传播，模型配置和密钥不会通过日程复制协议传播。已授权的 Web 工作台可以使用所在电脑的模型服务。配对码 90 秒有效、仅兑换一次；取消配对撤销后续授权，不能撤回已传播的日程副本。详细连接步骤见[设备配对](device-sync.md)。

## 密钥保存与备份

个人 API Key 使用 AES-256-GCM 加密保存在当前电脑，认证数据绑定日程空间。读取接口仅返回掩码和配置元数据；浏览器不把 Key 写入 localStorage 或 sessionStorage。电脑调用模型时仍需解密，因此只应向自己信任的设备和模型服务填写 Key。

本机默认在数据库同目录生成 `model-encryption.key`；安装版通常位于 `%LOCALAPPDATA%/Shunshoupai/data/`。备份需要同时保留 SQLite 数据库和这份密钥。也可用 `MODEL_SETTINGS_ENCRYPTION_KEY` 指定固定的 32 字节随机值的 Base64；已有密文依赖原密钥，不要随意更换。密钥丢失后需恢复原备份或重新填写模型 Key。

设备身份签名不提供 HTTP 加密。当前设备直连以可信局域网为边界，不能把身份验证当作 TLS 或端到端加密。源码本机授权密钥另见[桌面开发说明](desktop.md)，它不应交给浏览器或模型服务。

## 本地模型

默认允许解析为公网地址的 HTTPS 模型接口，拒绝重定向、元数据地址及未授权的私有地址。确需访问自己控制的本地模型，可在电脑 Node 进程中设置：

```dotenv
AI_ALLOWED_PRIVATE_HOSTS=localhost,127.0.0.1
```

重启后端后才可填写相应地址，例如 `http://127.0.0.1:11434/v1`。允许列表只填主机，不含协议或端口；这里的环回地址指电脑，不是手机。

## 旧版与验证

v1.x 的账号模型配置、Supabase 及扫码临时会话属于历史实现。v2 沿用被选择的旧本机空间及密文归属，不提供 Supabase 运行模式或自动导入界面，见[旧云端资料说明](cloud-setup.md)。

自动化使用受控模型验证配置、脱敏、Key 留空复用、版本冲突和固定提示词，不使用真实个人 Key 或付费模型。真实服务商的网络、额度和效果需自行验证；完成范围见[验收记录](acceptance.md)。
